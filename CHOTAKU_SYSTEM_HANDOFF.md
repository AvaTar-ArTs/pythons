## SYSTEM ARCHITECTURE

### LAYER 1: IDENTITY MEMORY ENGINE (CRITICAL)

**Purpose:** Persistent creative memory

**Stores:**
- Artist identities
- Character lore
- Voice styles
- Recurring phrases
- Emotional patterns
- Genre signatures
- Visual identities
- Pronunciation mappings
- Story arcs

**Example Data Structure:**
```json
{
  "artist_id": "gimpee_chaplinski",
  "name": "Gimpee Chaplinski",
  "born": 1946,
  "voice_style": "Polish-American tavern storyteller",
  "pronunciation": {
    "Leonard": "Lenard",
    "Gimpy": "Gimpee",
    "carving": "CAHR-ving"
  },
  "themes": [
    "wood carving",
    "dirty dad jokes",
    "polka tavern humor",
    "neighborhood stories"
  ],
  "recurring_locations": [
    "Pulaski Tavern",
    "the wood shed",
    "the back porch"
  ],
  "running_jokes": [
    "Who's carvin the wood?",
    "That's what she said",
    "Back in Poland..."
  ],
  "instrumentation_signature": {
    "primary": ["accordion", "tuba"],
    "supporting": ["clarinet", "drums"]
  },
  "energy_baseline": "escalating chaos to crowd chant"
}
```

### LAYER 2: VECTOR MEMORY DATABASE

**Purpose:** Semantic creative recall

**Technology:** PostgreSQL + pgvector (or ChromaDB, Qdrant)

**Stores:**
- Previous lyrics
- Generated prompts
- Visual prompts
- Generated assets
- Scene descriptions
- Melodies
- Character dialogue
- Thumbnails
- SEO metadata

**Enables:**
- Continuity retrieval ("What did Gimpee say last about carving?")
- Callback generation ("Generate a callback to episode 47")
- Lore consistency checking
- Recurring motif tracking

### LAYER 3: ORCHESTRATION ENGINE

**Purpose:** Creative conductor

**Flow:**
```
User Prompt
  ↓
[Retrieve Artist Memory]
  ↓
[Retrieve World Lore]
  ↓
[Retrieve Previous Assets]
  ↓
[Generate Song Concepts]
  ↓
[Generate Lyrics]
  ↓
[Generate Structure & Instrumentation]
  ↓
[Generate Music Prompt]
  ↓
[Send to Music Engine]
  ↓
[Store Outputs in Memory]
  ↓
[Generate Visual Assets]
  ↓
[Generate SEO Assets]
  ↓
[Generate Social Clips]
  ↓
[Ready for Publishing]
```

### LAYER 4: MUSIC GENERATION CONNECTOR SYSTEM

**Strategy:** Bridge, don't build (initially)

**Commercial Integrations:**
- Suno (API)
- Udio (API)

**Open Source Integrations:**
- AudioCraft / MusicGen
- EnCodec
- Amphion
- InspireMusic

**Why:** Avoid competing with music generation. Focus on orchestration and continuity.

### LAYER 5: STYLE TRANSLATION ENGINE

**Purpose:** Convert vague ideas into structured generation instructions

**Example:**

Input: "Funny old Polish wood carving tavern song"

Output:
```json
{
  "genre": "Comedy Polka",
  "tempo": 165,
  "time_signature": "2/4",
  "instrumentation": [
    "accordion (lead)",
    "tuba (bass)",
    "clarinet (melody support)"
  ],
  "song_structure": "call-and-response",
  "vocal_style": "crowd tavern chant with narrator",
  "energy_curve": "building → peak chaos → crowd participation",
  "humor_style": "dirty jokes, unexpected callbacks, crowd participation",
  "cultural_reference": "Polish-American tavern tradition"
}
```

## TECHNOLOGY STACK

### Backend
- **Language:** Python 3.12
- **Framework:** FastAPI
- **Database:** PostgreSQL + pgvector
- **Cache:** Redis
- **Task Queue:** Celery
- **Async:** asyncpg, aiohttp

### Frontend
- **Framework:** Next.js 14+
- **Styling:** Tailwind CSS
- **State:** TanStack Query
- **Auth:** Supabase Auth
- **Deployment:** Vercel

### AI/ML Stack
- **LLMs:** OpenAI, Anthropic Claude, Ollama
- **Music:** AudioCraft, MusicGen, Suno API
- **Images:** DALL-E 3, Midjourney API
- **Video:** Sora API
- **Voice:** ElevenLabs API

### Vector Memory
- **Primary:** PostgreSQL + pgvector
- **Secondary:** ChromaDB (local) or Qdrant (scalable)

### Integrations
- **YouTube:** YouTube Data API v3
- **TikTok:** TikTok Creator API
- **Instagram:** Instagram Graph API
- **Merch:** Printful API, Redbubble API
- **Email:** SendGrid or Postmark
