  updater-pro.sh recursively kills only child processes:

  /Users/steven/scripts/updater-pro.sh:69

  /Users/steven/scripts/updater-pro.sh:121

  mac-cleanup-pro.sh directly removes .pyc, caches, package data, and

  2. user approval;
  3. reversible quarantine;
  4. deletion manifest;
  5. restore command.

  ### Highest-risk findings

  #### 1. all_for_csv.py exposes destructive cleanup

  The CLI passes the default --dry-run value directly:

  cleanup_backups(args.directories, dry_run=args.dry_run)

  Because args.dry_run is false unless supplied, running:

  python all_for_csv.py ROOT --cleanup

  can remove backup files.

  This is the most important safety issue. Cleanup should require an explicit
  flag such as:

  --apply-cleanup

  and should create a manifest before deletion.

  #### 2. Deduplication is nondeterministic

  all_scan_v2.py uses as_completed() and treats the first completed file as
  canonical:

  rows[idx]["duplicate_of"] = paths[0]

  Thread completion order is nondeterministic, so repeated scans can select
  different canonical files.

  Canonical selection should be deterministic, for example:

  1. newest file;
  2. shortest path;
  3. lexicographic path;
  4. explicit user preference.

  #### 3. Symlink traversal is not fully controlled

  Several scanners use os.stat() and Path.resolve().

  A symlinked file can cause metadata, hashing, or content reads outside the
  requested root. Root paths should be validated with containment checks, and
  symlink behavior should be explicit:

  --symlinks skip
  --symlinks record
  --symlinks follow

  The default should be skip or record, not follow.

  #### 4. Full hashing and line counting can cause stalls

  doc-source-enriched.py limits classification samples to 64 KB, but then
  performs full-file hashing and full line counting.

  That can become slow on:

  - large generated files;
  - iCloud placeholders;
  - mounted external volumes;
  - giant JSON/CSV files;
  - media accidentally classified as text.

  Use configurable limits and record:

  hash_status=complete|skipped_size|error
  line_count_status=complete|skipped_size|error

  #### 5. Metadata scoring looks more authoritative than it is

  doc-source-enriched.py generates:

  - business value;
  - ROI;
  - complexity;
  - integration potential;
  - agent affinity;
  - skill affinity.

  These are heuristics based mainly on filename, path, category, confidence,
  and line count. They are useful for ranking, but should be labeled:

  heuristic_score

  rather than appearing as validated business intelligence.

  The older FULL_EXCLUDED_PATTERNS contains broad patterns such as:

  .*dist.*
  .*build.*
  .*out.*
  .*venv.*

  These can incorrectly exclude legitimate filenames or project paths.

  The newer anchored directory/file patterns are better, but the legacy
  scanners still use the old rules. This creates inconsistent inventories
  depending on which script is run.

  - legacy Filename, File Size, Original Path;
  - enriched 45/46-column metadata;
  - v2 media schema;
  - explicit-path inventory schema.

  schema_version=2

  root_id
  path
  relative_path
  kind
  extension
  size_bytes
  mtime
  birthtime

  hash_status

  ### Critical findings

  #### 1. Destructive cleanup is insufficiently gated

  all_for_csv.py can remove backup files through:

  python all_for_csv.py ROOT --cleanup

  It should require an explicit --apply-cleanup flag and generate a manifest
  before moving or deleting anything.

  The music enforcement script also moves unmatched MP3s automatically:

  /Users/steven/pythons/seLLeable-item-rxtractor/enforce_csv_cleanup.py:124

  There is no dry-run mode, restore command, or pre-move manifest.

  #### 2. Product builders make unverified commercial claims

  build_products_from_csv.py generates README text claiming files are:

  > production-ready, tested, documented

  That is not established by the CSV metadata or tests.

  It also generates generic licenses and placeholder support addresses:

  support@yourdomain.com

  The product builder must distinguish:

  observed
  tested
  packaged
  commercially verified

  #### 3. Hardcoded local paths prevent portability

  Examples:

  - /Users/steven/MasterxEo
  - /Users/steven/p-market
  - /Users/steven/Music/nocturneMelodies
  - /Users/steven/marketplace-uploader
  - /Users/steven/iterm2-fix

  These should become CLI arguments or configuration:

  product-builder \
    --source-csv inventory.csv \
    --output-dir ./dist \
    --source-root /Users/steven/pythons

  #### 4. Product selection is keyword-based, not capability-based

  extract_sellable.py categorizes files using filename/path substring
  matches.

  That causes:

  - false positives;
  - duplicate products;
  - unrelated scripts bundled together;
  - no dependency or entry-point validation;
  - no license/provenance check.

  The rename and inventory data already show duplicate concepts such as many
  versions of organizer, Instagram, analyzer, and image tools.

  #### 5. Bundle builder flattens files and can change behavior

  build_products_from_csv.py copies scripts into a flat src/ folder. Two
  files with the same name receive suffixes:

  tool.py
  tool_1.py

  This can break imports and relative file references. Product bundles need
  either:

  - preserved source paths; or
  - an import-rewrite/package assembly phase.

  #### 6. Music matching is too permissive

  The music scripts match tracks using partial title words and album
  similarity. A single matching word can identify a track.

  That creates a risk of:

  - wrong MP3-to-catalog associations;
  - duplicate track assignment;
  - false “missing” reports;
  - incorrect album packaging.

  Matching should use a confidence score and require explicit approval below
  a threshold.

  #### 7. Music licensing is not verified

  The generated product says:

  Commercial use permitted
  Sync licensing
  Streaming distribution

  Those rights must be verified against the actual generation platform terms
  and ownership records before selling. The scripts currently treat the CSV
  as authority, but a CSV proves catalog membership—not legal licensing
  rights.

  #### 8. SEO thumbnail code is not production-ready

  /Users/steven/pythons/seo_marketing/thumbnail.py has several issues:

  - wildcard MoviePy import;
  - missing local modules such as settings and lexica;
  - downloads NLTK data at runtime;
  - uses randomness, so output is not reproducible;
  - no CLI arguments;
  - fixed 1280×720 layout;
  - possible failure when title text exceeds expected ranges;
  - likely depends on older MoviePy APIs.

  It should become a deterministic renderer with explicit input/output
  configuration and a locked dependency environment.
